# 「設定」画面に「設定リンクを貼り付けて適用」欄を追加する（v1.5.2）

## 背景
- 2026-10-20、ユーザーが iPhone 16 Pro（ホーム画面にアプリを追加済み）で、現在のトークンの設定リンク（店舗のQR）を開いて試したところ、**ホーム画面のアプリには設定が反映されなかった**。QRで開くとSafariでアプリが開き、設定はSafari側にだけ入る（README 不具合ログ#7）。
- このままでは、トークンの更新（2026-10-16 の判断・検収手順書 ⓪-13）のたびに、iPhoneの端末には40文字のトークンを手で入力することになる。全店で最大29台あり、現実的でない。
- 2026-10-16 の判断記録で「提案止まり」としていた貼り付け欄を、2026-10-20 にオーナーが承認した。条件は次の3つ。
  - 貼り付けた内容（トークンを含む）は、適用後に欄から消し、画面や履歴に残さない。
  - リンクの渡し方（AirDrop・社内チャット等）の運用と、社外のサービスや全員が見られる場所に貼らない注意を、手順書のN段階に書く。
  - 必要なら操作ガイドにも手順を加える。

## 決定内容
- 「設定」画面の「接続テスト」の下に「📋 設定リンクを貼り付けて設定する」を置く。押すと欄が開き、「適用する」と「やめる」が出る。
- 反映の処理は、**リンクを開いたときと共通**の `applySetupParams()` を使う。書き換えるのは提出先URL・トークン・拠点だけで、担当者名・棚卸データ・マスタには触れない。
- 受け付ける貼り付けは、`#setup=1` を含み、提出先URL（http(s)）とトークンの両方があるものだけ。
  - リンク全体でも、`#` から後ろだけでもよい。前にチャットの文などが付いていても、`#` から後ろを読む。
  - 拠点が許可リストに無ければ（末尾に余計な文字が付いて拠点に混ざった場合も含む）、何も変えずに断る。
- **貼り付けた内容を残さない**ための扱い:
  - 「適用する」を押した時点で、成功・失敗にかかわらず欄を空にする。「やめる」・画面の移動・アプリが裏に回ったときも空にする。
  - 欄は伏せ字（`-webkit-text-security: disc`）で表示し、`autocomplete`・`autocapitalize`・`autocorrect`・`spellcheck` を切る。
  - 貼り付けた内容はどこにも保存しない。エラーの記録にも残さない。アドレスバー・履歴も変わらない。
  - 適用に成功したら、クリップボードを空にすることを試みる。端末が許さない場合のために、手順書でも上書きの仕方を案内する。
- 運用（検収手順書 ⓪-13 のN段階）: iPhoneでホーム画面のアプリを使う端末は、貼り付けで再設定する。リンクの渡し方は次の順に使う。
  1. 掲示のQRからカメラで「開かずにコピー」（送らずに済むので推奨）
  2. 社内チャットの1対1のメッセージ（貼り付けた後、双方で削除）
  3. 店内で対面のAirDrop

  社外の個人向けサービス・メール・グループやチャンネル・掲示板・紙への書き写し・画面の写真は使わない。
- 操作ガイドに、ページ6「iPhoneのホーム画面のアプリで設定する」を追加した。ページ5の注記から案内する。印刷用PDFは6ページになる。
- GASは変更しない。版は 1.5.2（`CACHE_VERSION` も更新）。

## 却下した案とその理由
- **クリップボードを自動で読む**（ボタン1つで適用） … iPhoneでは毎回ペーストの許可を求められ、Androidでは権限の許可が要る。貼り付けは利用者の操作に任せたほうが、何を入れたかが分かりやすい。
- **欄を伏せ字にしない** … リンクにトークンが入っている。売場で画面をのぞかれたり写真に撮られたりするのを避けるため、伏せ字にする。
- **拠点が正しくないリンクでも、ほかの値（URL・トークン）は反映する**（リンクを開いたときと同じ扱い） … 貼り付けでは打ち間違いや別の文字の混入が起き得る。誤った値で一部だけ書き換わると、原因が分かりにくくなる。
- **トークンだけを入力する欄を別に設ける** … 40文字の手入力になり、今回の目的（手入力をなくす）に合わない。トークン欄は従来どおり残っている。
- **iPhoneのホーム画面のアプリを削除して、QRで設定してから追加し直す** … 削除すると端末の棚卸データとマスタも消える。QRで設定した直後に追加した場合に設定が引き継がれるかも確かめていない。

## 影響範囲
- `index.html`（貼り付け欄）・`css/style.css`（`.masked`）・`js/app.js`（`applySetupParams`・`applyPastedLink`・`clearPastedLink`。`applySetupLink` は共通処理を使う形にした）・`sw.js`（`CACHE_VERSION`）。
- 文書: README（設計判断#31・不具合ログ#7・初期設定の方法A-2・v1.5.2のまとめ）、CLAUDE.md（変更時の注意・検収13-2）、検収手順書（⓪-13 のN段階とリンクの渡し方、⓪-14 の新設）、`docs/操作ガイド.html`（ページ6）。
- 既存の動き: 設定リンクを開く経路は、共通処理に置き換えた後も同じ動きであることを確かめた（拠点・トークンが入り、アドレスバーから `#…` が消える）。同期・提出も変わらない。
- **既知の残り**:
  - 「設定」画面の「提出用トークン」欄は、従来どおりトークンを平文で表示する。貼り付けの後もそこにトークンが見える。管理者がPCで手順 M-2 のコピーに使っているため、今回は変えていない。伏せ字にするかは別途相談する。
- 実機でしか確かめられない点（検収手順書 ⓪-14）:
  - iPhoneのカメラで、QRのリンクを開かずにコピーできるか（S-2）。
  - iPhoneのペーストと伏せ字の見え方（S-3）。
  - クリップボードが空になるか（N-6）。
  - Androidのホーム画面のアプリにQRの設定が入るか（不具合ログ#7 の「分かっていないこと」）。
